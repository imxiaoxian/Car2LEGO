# 车辆物理资料

`assembly_v3` 在车型识别完成后、生成参考图之前，自动执行项目内的 `research-vehicle-specifications` skill。用户输入品牌、车型后提交设计，后台实际执行联网搜索并读取原文，将找到的尺寸作为生成输入。年款选填，未填时保存为空，不代入当前年份或其他默认年份。物理资料区用于展示搜索结果和规划依据。

Skill 文件位于 `backend/app/skills/research-vehicle-specifications/SKILL.md`，运行入口为 `app.services.vehicle_research.collect_physical_profile`。公开搜索入口使用 DuckDuckGo，失败后使用 Bing；无关品牌结果不计为成功搜索。浏览器和后端 HTTP 出口的可访问性可能不同；当前 HTTP 环境访问 Ferrari 首页和 F40 页返回 403，浏览器导航成功本身不能证明正文可读。系统记录 `https://www.ferrari.com/zh-CN` 作为品牌入口，车型链接来自搜索结果和已知来源；尚未自动解析首页链接或通过浏览器回退采集，品牌首页本身不会被当作 F40 尺寸证据。

按照比例要求搜索整车长宽高/轴距、前后轮距/轮胎/轮毂、风挡尺寸/角度、门板尺寸/开启角、座椅和发动机包络。首轮阅读资料后，针对剩余未知项搜索维修手册、技术 PDF 和尺寸图。每次记录实际查询词、搜索结果链接、来源读取状态与缺失项。搜索摘要只用于找来源，数值证据必须来自下载的原文。

结构化 HTML/text 先用确定性解析器读取；普通文段及可提取文字的 PDF 使用配置的 `gpt-6.1-sol`，加载该 skill 后提取结构化尺寸。代码检查原文引句、数值、车型和年款依据，模型无法用自填来源或编造引句获得可信状态。检索阶段不生图。

## 数据范围

共 22 类：长宽高、轴距、前后轮距、前后轮胎外径/宽度、前后轮毂直径、车门长度/含玻璃高度/开启角、前风挡宽度/斜高/倾角、座椅宽度和发动机包络长宽高。

- 长度以毫米保存，以 `实车毫米 / 比例分母 / 0.4` 换算 LDU。
- 前风挡角以水平面为基准；来自竖直面的倾角先转换。角度不随比例缩放。
- 车宽需明确不含后视镜；未知宽度定义不能用于精确尺寸验收。
- 轮胎标号分别解析前后轴。外径为轮毂英寸乘 25.4 加两倍名义胎壁高度，不代表受载滚动半径。
- 每条测量保存来源 URL、来源类别、原文证据、单位、测量定义、取得方式、年款范围、车型匹配与置信度。
- 缺失单位、缺失角度基准、多车型信息框、多变体尺寸和年款不匹配的数据不自动当成精确值。相互冲突的来源保留在报告中。
- 用户补录值标为 `provided`，即使请求声称已抓取，也不会自动升级为来源已复核。

## 接口

`GET /api/v1/research/physical-specifications?make=Ferrari&model=F40&year=1990&scale=1:24` 读取缓存。

`POST /api/v1/research/physical-specifications` 采集或补录：

```json
{
  "make": "Ferrari",
  "model": "F40",
  "year": 1990,
  "scale": "1:24",
  "collect_sources": false,
  "measurements": [
    {
      "name": "windshield_rake",
      "value": 30,
      "unit": "deg",
      "angle_reference": "vertical",
      "method": "estimated",
      "source_kind": "user",
      "vehicle_match": "unconfirmed",
      "evidence": "构造示例，不是 F40 实测数据"
    }
  ]
}
```

这是可选补录示例，不应写入真实车型资料。通常只需提交 `make`、`model`、`scale`，`year` 可以省略或为 `null`，默认执行联网搜索，无需用户输入尺寸。`source_urls` 可提供最多 6 个厂商或认可汽车资料站的 HTTPS URL；HTML/text 最多 2 MB，PDF 最多 8 MB，跟随重定向前重新校验域名。技术 PDF 提取前 80 页、最多约 12 万字符；扫描 PDF、纯图片尺寸图和图像标定尚不自动解析，保留不可读取的记录。

`VEHICLE_RESEARCH_SOURCE_LIMIT` 默认为每次读取最多 12 个来源；`VEHICLE_RESEARCH_MODEL_EXTRACTION=true` 启用文本模型提取。不需要单独的搜索 API key；文本提取使用已有 OpenAI 配置，并计入设计任务的文本调用次数。搜索服务不可用时明确记录失败，仍可尝试已知来源，缺失值保留未知。

## 装配与验收

缓存存于 `storage/vehicle_specs/<品牌、车型与可选年款哈希>.json`，独立于历史 `CarSpec` 表。首页切换车型只更新表单，提交设计后才触发资料检索。不同品牌、车型或年款使用独立缓存；已有完成且覆盖当前所需字段的缓存可复用。旧 skill 版本、搜索中断或新比例需要更多字段时，新设计会自动搜索；详情搜索按钮始终重新检索。未指定年款时记录来源的世代范围；不相交的世代资料不能混合为精确约束。每次新设计将解析结果快照存为 `physical_specifications.json` 并写入任务检查点，恢复时复用该快照。已保存参考图的旧任务不自动切换资料。

有依据的整车尺寸进入 OR-Tools 比例网格；有依据的部件尺寸写入 `planning.physical_constraints`，同时提供给外观描述、生图和一致性检查。风挡斜高与倾角可换算垂直升高和水平投影。轮胎的实际原生几何与目标尺寸比较，超过 5% 标为失败。现有固定轮组配方不会被任意拉伸来消除误差。

门板精确包络、玻璃表面和开启机构仍需要专用装配配方与测量。组合座舱零件的包围盒不等于风挡玻璃尺寸，因此这些检查保持未验证。有数据参与规划不等于该部件已实现或 `.io` 已完成精细验收。

桌面详情页“原厂尺寸与结构资料”区显示实车值、当前比例目标、搜索记录、原文来源和未找到的尺寸。搜索按钮可重新检索车型；新资料供后续设计使用，不改写现有模型。官网 403、机器人检查及其他访问失败会保留错误记录。资料搜索与模型几何验收是独立阶段，搜索成功不代表 `.io` 已通过验收。
