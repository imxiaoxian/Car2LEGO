# GPT + Blender MCP experiment

## Implementation

This branch adds `gpt-blender` as an explicit reconstruction backend. The desktop
experiment selects it through `CAR2LEGO_RECONSTRUCTION_BACKEND=gpt-blender`.
The existing default remains `hunyuan-mv` when this variable is absent.

Vehicle dimensions now come directly from Responses API dialogue, using the
original project's API configuration. The request supplies no browsing tools.
Year is optional. Every returned number is an estimate with a confidence and
basis; it does not certify manufacturer specifications. See
[vehicle dialogue](vehicle-spec-search.md).

The modelling request supplies four labelled elevations, the overview image and
the full-size specification snapshot to `CAR2LEGO_BLENDER_MODEL`, now defaulting
to `gpt-6-astra`. Initial modelling, execution repairs and visual review use the
same selected model. Vehicle dialogue continues to use `OPENAI_MODEL` independently.
Modelling dialogue streams its response, with a 180-second SDK idle/read timeout
and a 1,800-second elapsed-time limit checked on each received event.
The earlier comparison below was generated by `gpt-6.1-sol`. Generated bpy code runs
through the upstream MCP `execute_blender_code` tool and Blender addon. Execution
errors can trigger two corrections. After exporting six views, a visual review
can apply one scene patch. Failed patches restore the saved coherent scene.

The upstream dependency is
[ahujasid/mcp-for-blender](https://github.com/ahujasid/mcp-for-blender), MIT,
v2.1.9, commit `7a0373ec9199183cb460068c4f96aed9c579fb4f`.
The addon is loaded in the experiment's Blender process. Preferences, logs and
outputs are isolated per run. No global addon installation is required.
Generated code is restricted by AST checks, which are not a security sandbox;
this is a local modelling experiment using a trusted configured endpoint.

## Setup And Run

Install normal pipeline dependencies and `.[gpt]`. Blender 4.5 is required.
The MCP subprocess uses an isolated environment to avoid conflicts with the
original project's Python dependencies:

```powershell
uv venv .mcp-venv --python 3.11
uv pip install --python .mcp-venv/Scripts/python.exe "mcp>=1.26,<2" httpx
```

Set these paths in the ignored local `.env`, adapting to the local checkout:

```dotenv
CAR2LEGO_SOURCE_ROOT=D:/lego
CAR2LEGO_SOURCE_PYTHON=D:/python/anaconda/python.exe
CAR2LEGO_MCP_PYTHON=D:/Car2LEGO_3D-worktrees/gpt61-blender/.mcp-venv/Scripts/python.exe
CAR2LEGO_BLENDER=D:/lego/backend/storage/tool_research/blender-4.5.14-windows-x64/blender.exe
CAR2LEGO_RECONSTRUCTION_BACKEND=gpt-blender
CAR2LEGO_BLENDER_MODEL=gpt-6-astra
```

API credentials are inherited from the original project's configuration and are
not stored in the experiment's request records. Use the experiment's installed
Python package; when sharing another checkout's interpreter, set `PYTHONPATH`
to this checkout's `src` first.

```powershell
python -m car2lego3d research --brand Lotus --model "For Me" --output runs/spec
python -m car2lego3d reconstruct --backend gpt-blender `
  --views path/to/01-image/views.json --vehicle-specs runs/spec/spec.json `
  --output runs/mesh
python -m car2lego3d lego --mesh runs/mesh/calibrated.glb `
  --vehicle-specs runs/spec/spec.json --reference-views path/to/01-image/views.json `
  --scale 1:24 --strategy car --color 25 --output runs/lego
python -m car2lego3d studio --ldraw runs/lego/model.ldr --output runs/studio
```

For image generation and all subsequent stages together, use `run --backend
gpt-blender --prompt ... --vehicle-specs ... --scale 1:24 --strategy car` with
an empty output directory. The existing GPT image service remains unchanged.

## Astra Switch On 2026-10-15

Blender modelling now defaults to `gpt-6-astra`, selected separately through
`CAR2LEGO_BLENDER_MODEL`. The initial script, execution repairs and visual review
all use that model. Request records and reconstruction metadata include the
selected model, and completed responses from another model are not reused.
Vehicle dialogue still uses `OPENAI_MODEL`; its local value remains `gpt-6.1-sol`.
The original GPT image generation configuration is unchanged.

The configured gateway listed `gpt-6-astra`. Real text and reference-image smoke
requests completed and reported `gpt-6-astra` in their responses. Evidence is in
`runs/lotus-astra-api-smoke/` and `runs/lotus-astra-vision-smoke/`.

The first two full Lotus attempts exposed a timeout failure: the non-streaming
Responses call kept the client blocked while Astra generated a long Blender
script. The modelling request timed out at 303.925 seconds and again at
605.404 seconds after only the request deadline was increased. The fix keeps
the Responses request streaming, writes every event to `model-events.jsonl`,
and updates `model-progress.json` while the model is working. The stream uses
the terminal `response.completed` event, so gateways that omit
`response.created` still complete correctly. Processing stops at a terminal
event without waiting for socket EOF. A 180-second SDK read timeout handles an
idle connection, and a 1,800-second elapsed-time limit is checked on each received
event; it does not independently interrupt a blocked read. Interrupted streams
retain progress and events, fail without parsing partial JSON, and invalidate
older completed replies before a replacement request can be cached.

The successful rerun is `runs/lotus-astra-stream2-20261015/`. It reuses the existing
GPT-generated images and the saved vehicle specification; image generation and
vehicle dialogue were not repeated. The Astra model
response completed in 227.406 seconds (8,798 events), visual review completed
in 67.297 seconds (1,973 events), and the run continued through
`03-lego/model.ldr` and `04-studio/model.io`. Blender MCP calls now use a
600-second socket budget by default, configurable with
`CAR2LEGO_MCP_TIMEOUT`. A local launch adapter overrides the pinned upstream
server's hardcoded 180-second socket timeout without editing its checkout or
the standard library. The MCP client allows another 15 seconds, and the parent
subprocess guard adds 30 seconds for shutdown and file writing. This removes
the old 180/240/280-second socket, client and process boundaries.

A real MCP smoke call using the new adapter completed in 188.312 seconds,
including a deliberate 185-second delay inside Blender before adding a cube.
This verifies that execution can cross the previous 180-second socket boundary;
it is a constructed latency test, not another generated vehicle. Its request,
response and Blender log are in `runs/astra-timeout-mcp-smoke-20261015/`.

The completed run is an engineering validation rather than visual delivery
acceptance: its report keeps `appearance_accepted=false`, `buildability=unverified`,
and `studio_open_verified=false`. The generated Studio archive is valid on an
LDraw round trip, but it still requires the planned visual and physical checks.

After the streaming and MCP timeout changes, all 187 backend tests pass (14
existing warnings from matplotlib remain). The focused dialogue and Blender
suite has 24 passing tests, including terminal-event handling, progress files,
interrupted-stream retries, model separation, cache invalidation, timeout
forwarding, and isolation of the upstream socket override. This change
remains on the experimental branch; `main` is not merged.
