# 联网车辆规格搜索

网页输入品牌、车型和可选年款/版本后，停止输入 1.6 秒触发项目内
`.agents/skills/vehicle-spec-search/SKILL.md`。首次默认车型可点击“搜索规格”。
年款/版本为选填，留空时直接按品牌和车型搜索；只有实际存在代际或车身版本歧义时才提示澄清。
本机 Codex CLI 读取 skill 的流程，通过 `car2lego3d.web_access search/open` 实际请求
Bing 搜索页及来源页面，输出严格 JSON；网页不维护车型规格白名单。

需要已安装并登录的 Codex CLI，及能运行工具调用的配置模型。使用本机既有模型提供方；
检索会消耗该提供方的模型额度。`CAR2LEGO_CODEX_BIN` 可指定 CLI 可执行文件。
命令使用只读沙箱、不交互审批；项目 skill 仅允许搜索与读取网页。
本机直连 ChatGPT 和托管搜索不可用，因此使用公共 HTTP 搜索/读取适配器。
适配器限制为公开 HTTP(S) HTML 来源，逐跳检查地址，限制下载量和超时。

## 结果与绑定

- 核心尺寸：车长、车身宽度、车高、轴距。轮距、轮胎、车门、玻璃、座椅和发动机外廓均尝试检索。
- 官方资料标记 `manufacturer`，第三方发布资料标记 `reported`；都不代表独立实测。
- 数值必须带来源 URL、简短原文证据、单位和换算说明；证据必须出现在实际打开的页面文本中。
- 未获取的数值为 `null/unknown`，不从图片猜测；多代或多版本无法确定时返回澄清问题。
- 仅含后视镜宽度不能作为车身宽度；未说明宽度基准时保留该限制说明。
- 一个服务每次只检索一个车型。精确品牌/车型/版本和 skill 版本一致时可复用成功结果；点击重新搜索强制刷新。
- 改变车型/版本立即使旧结果失效。搜索失败不会使用静态规格，也不会允许生成。
- 生成前保存规格副本、身份和规格指纹。比例规则与自定义车长规划均读取该副本。

`runs/vehicle-research/<ID>/research/` 保存结构化 schema、CLI 搜索事件、模型答案、规格及结果。
成功网页结果不包含来源全文，来源文本及工具记录仅保留在本地运行日志。
生成产物 `00-vehicle/spec.json` 和网页的“物理规格”下载可追溯到本次检索。
