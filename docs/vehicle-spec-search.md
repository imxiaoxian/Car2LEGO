# 车辆参数对话

默认 `research`、桌面生成和详情页获取参数均直接调用配置的大模型。
原联网 skill、搜索适配器和历史来源校验器保留供复查，但默认路径不调用它们。

配置按进程环境、本项目 `.env`、原项目 `backend/.env` 顺序读取：
`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。默认模型为 `gpt-6.1-sol`。
通过 Responses API 对话，只请求普通 JSON，使用本地 schema 和物理约束校验。
不会发起搜索请求，也不依赖 Codex CLI 登录。

```powershell
python -m car2lego3d research --brand Lotus --model "For Me" --output runs/lotus-specs
```

年款和版本为选填，可通过 `--variant` 补充。未指定时，回答需说明所假定的代表版本。
27 项字段包括长宽高、轴距、轮距、前后悬、轮胎宽度/扁平比/轮毂直径、
车门尺寸和位置、前风挡大小及倾角、座椅及发动机包络。

所有数值均为 `estimated`，包含单位、置信度和依据。模型知识中的常见规格也不标为原厂核验。
未知为 `null/unknown`、置信度 0，不填虚构 URL。近期车型可能存在较大知识误差。
数值校验包含实车毫米尺度、字段完整性、单位、轮胎三参数和前悬+轴距+后悬关系。
首次不合规可进行一轮纠正；失败不会回退到静态车型规格。

缓存绑定品牌、车型、版本、模型、API 地址、提示词和 schema；重新获取会刷新缓存。
改变车型或版本后必须重新获取。默认流程不会复用旧联网搜索缓存。
比例规划和装配读取规格快照，各比例保留自己的尺寸容差与结构要求。

`runs/vehicle-research/<ID>/research/` 保存请求、完整模型回答、`dialogue.json`、
`spec.json` 和 `result.json`。密钥不写入这些记录。
