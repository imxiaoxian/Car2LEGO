## 与原 Car2LEGO 的关系

原项目在 `backend/app/services/assembly_v3/pipeline.py` 中通过参考图、外观规格、车辆装配配方和验证导出模型。新项目保留真实零件目录、LDraw 导出、独立验收状态和哈希记录的设计原则，增加显式的图片重建网格作为中间表示。

新流程：提示词 → 单张完整车图 → 背景移除 → TripoSR 三平面重建 → 带颜色三角网格 → 各向异性体素 → 标准板件覆盖 → LDraw / BOM / 连接报告。

这是独立研究项目，不复制原项目的服务、数据库、密钥、Studio 零件库或未提交代码。标准板件覆盖算法和导出代码在本项目内实现，网格与体素操作使用成熟的 `trimesh` / `scikit-image` 库。

## Windows 复现改动

TripoSR 原始依赖要求编译 `torchmcubes`，`run.py` 还会无条件引入本实验不使用的 UV 烘焙依赖。适配器直接调用原始 `TSR` 模型，用 `scikit-image.measure.marching_cubes` 提取网格，并匹配上游两次轴反转的约定。模型结构、权重、float32 推理、密度阈值和顶点颜色采样保持上游默认。这属于 Windows 适配复现，不是逐行运行原始 `run.py`。

每阶段独立进程，保证生图权重退出后再加载重建权重。默认提取分辨率为 128，低于上游的 256；允许通过参数提高质量。CPU 执行网格提取，神经网络仍使用 CUDA。背景移除使用 `rembg` 的 U2NetP；透明输入直接复用 alpha。

## 可检验假设和边界

1. 显式网格可提供一致的长度、宽度、高度与轮廓，减少参考图直接驱动配方时的几何自由度。需要以后与原流程同车型比较，当前不声称已证明更好。
2. 单图背面和遮挡部分由模型推断；生图车辆细节也可能偏离指定车型，不能解释为工程尺寸或真实 CAD。
3. 当前输出是车形板件雕塑，车轮也是网格体素的一部分。未自动实现可转车轮、转向、车门、悬挂、内骨架或精确曲面零件匹配。
4. 贪心板件覆盖与 stud 连接图只是基础数字检查；同层相邻板件不算连接。断连或缺少下层支撑会明确记录，没有通过实物可搭建验收。
5. GLB 和静态板件预览使用板件包围盒。LDraw 文件引用真实标准零件，必须在 Studio 或独立 LDraw 渲染器中检查真实几何。
6. 后续重点：多视图几何一致性、车辆部件分割、独立车轮替换、底盘支撑、跨层连接优化和斜坡/弧面零件拟合。

实际复现结果与输入输出哈希见 `reproduction.md` 和 `examples/`，不能以官方 A100 演示耗时替代本机测量。
